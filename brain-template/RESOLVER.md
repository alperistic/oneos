# RESOLVER

A routing rule: where does a given piece of information belong? Answer this before filing anything — it is what keeps agents from making an ad hoc call each time, and from producing duplicate homes for the same kind of information.

1. Actively built thing (product, feature, campaign) -> `projects/`
2. Reusable mental model or cross-domain synthesis -> `concepts/`
3. Decision with lasting rationale -> `decisions/`
4. Infrastructure, runbook, recurring operational task -> `ops/`
5. Raw import or snapshot, not yet distilled -> `sources/`
6. Unsorted quick capture, not yet triaged -> `inbox/`
7. Dead or historical, superseded by something newer -> `archive/`

Adapt this list to your own business — the point is that it's a short, written, deterministic list, not that it matches this exact shape. Whatever you use, keep the number of "does this belong here or there" ambiguous cases as close to zero as you can, and update this file the moment you notice a recurring judgment call.
